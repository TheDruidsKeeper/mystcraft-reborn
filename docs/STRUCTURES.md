# Facility structures: how rooms are sourced, imported and shipped

The Facility (docs/plans/FACILITY_PLAN.md) is a jigsaw structure whose pieces are **imported**, not designed here.
Pieces live in a built-in data pack, `src/main/resources/datapacks/mystcraft_facility`, registered by
`Mystcraft#addPackFinders` (enabled by default; players can disable it or layer their own packs on top).

```
datapacks/mystcraft_facility/
  pack.mcmeta
  manifest.json                         <- the only file you edit by hand (pools, weights, provenance)
  data/mystcraft/structure/facility/<pool>/<piece>.nbt
  data/mystcraft/worldgen/structure/facility.json
  data/mystcraft/worldgen/processor_list/facility/*.json
  data/mystcraft/loot_table/chests/facility_*.json
  data/mystcraft/tags/worldgen/biome/has_structure/facility.json
build/generated/sources/structurePools/datapacks/mystcraft_facility/   <- generated by Gradle, never committed
  data/mystcraft/worldgen/template_pool/facility/<pool>.json
  CREDITS.md
```

## Pool graph

| Pool | Role | Fallback |
|---|---|---|
| `facility/entrance` | start pool, surface building | `minecraft:empty` |
| `facility/shaft`, `facility/shaft_long` | vertical connector down to the lobby | `minecraft:empty` |
| `facility/lobby` | hub with several exits | `minecraft:empty` |
| `facility/rooms` | puzzle / trap rooms, chained until `size` runs out | `facility/vault` |
| `facility/vault` | terminal reward room | itself |
| `facility/sv_three_way_blocker` | sub-pieces of one Stonevaults room | itself |

Jigsaw joints: a piece's `jigsaw` blocks name the pool their neighbour comes from (`pool`) and the joint name the
neighbour must expose (`target`). Imported pieces keep their original joint names, remapped into `mystcraft:facility/…`
by the importer.

## Adding a room

1. Get the piece as `.nbt` (structure block / Axiom export), `.schem` (WorldEdit/Axiom) or `.litematic`.
   Only use sources whose license permits redistribution with attribution (MIT, LGPL, CC-BY; **not** ARR, GPL, NC).
2. Import it (needs `pip install nbtlib`):
   ```
   python scripts/structures/import.py --pool facility/rooms --weight 1 --prefix xx_ \
       --source-pack "Pack name" --author Author --license MIT --url https://... \
       --remap otherpack:dungeon/=mystcraft:facility/ path/to/piece.nbt
   ```
   The script prints any ids from foreign namespaces that are still referenced (pools, loot tables); provide those
   files or add `--remap` entries until the list is empty. Entities are stripped unless `--keep-entities`.
3. If the room needs puzzle markers, load it in a creative world with a structure block, place the DATA markers
   (FACILITY_PLAN §2.2), save with the structure block and re-import the saved file.
4. Optional: set a pool's `fallback` / default `processors` in `manifest.json` → `pools`. Vanilla pieces can be mixed in
   without files via `manifest.json` → `external` (`{"pool": "facility/rooms", "location": "minecraft:trial_chambers/…"}`).
5. Build. `generateStructurePools` regenerates the pool JSON and `CREDITS.md`; the smoke test fails if a pool references
   a missing template or processor list. Add the pack to `NOTICE.md` the first time it is used.

## Player-side extension

The pack is a normal data pack: a player pack placed above it can override any `template_pool/facility/*.json`
(add elements, change weights) or supply extra `structure/facility/**.nbt` files. The pool ids above are the public
contract and should not be renamed.
